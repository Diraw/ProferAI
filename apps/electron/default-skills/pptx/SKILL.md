# PPTX Skill

## Profer default visual conventions

Unless the user explicitly specifies a template, brand colors, or another style, `.pptx` files generated by Profer default to **Cloud Dancer Academic**. The complete design specification is in `workspace-files/.context/profer-ppt-design-system.md`; read that file before generating.

Minimum requirements:

- Use PptxGenJS to generate editable native objects; default to warm gray/off-white backgrounds (`E8E3D7` / `F2EFE7` / `D3CCBF`) and near-black text (`1D1C19`).
- Prefer square-corner `RECTANGLE` for text boxes, information blocks, and chart containers; do not default to walls of rounded cards, pill buttons, or bubble containers.
- Text boxes may use an extremely subtle low-offset outer shadow: `blur: 4–6`, `offset: 1–2`, `opacity: 0.10–0.16`; shadows should serve hierarchy separation, not decoration.
- The overall character must be bold, restrained, academic, and editorial; use Cloud Dancer illustrations only as a style reference or chapter visual, not as a full-page background on every slide.
- Still follow the per-slide claim–evidence relationship, real visual elements, grids, rendering QA, and delivery audit requirements.

## Design Ideas

**Do not create boring slides.** Plain bullet lists on a white background will not impress anyone. Consider ideas from this list for each slide.

### Before Starting

- **Pick a bold, content-informed color palette**: the palette should feel designed for THIS topic. If swapping your colors into a completely different presentation would still "work," you have not made the choices specific enough.
- **Dominance over equality**: one color should dominate (60–70% visual weight), with 1–2 supporting tones and one sharp accent. Never give all colors equal weight.
- **Dark/light contrast**: use dark backgrounds for title and conclusion slides and light backgrounds for content (a "sandwich" structure), or commit to dark throughout for a premium feel.
- **Commit to a visual motif**: pick ONE distinctive element and repeat it—rounded image frames, icons in colored circles, or thick single-side borders. Carry it across every slide.

### For Each Slide

**Every slide needs a visual element**—an image, chart, icon, or shape. Text-only slides are forgettable.

**Layout options:**
- Two-column (text left, illustration on right)
- Icon + text rows (icon in a colored circle, bold header, description below)
- 2x2 or 2x3 grid (image on one side, a grid of content blocks on the other)
- Half-bleed image (full left or right side) with content overlay

**Data display:**
- Large stat callouts (big numbers 60–72pt with small labels below)
- Comparison columns (before/after, pros/cons, side-by-side options)
- Timeline or process flow (numbered steps, arrows)

**Visual polish:**
- Icons in small colored circles next to section headers
- Italic accent text for key stats or taglines

### Typography

**Choose an interesting font pairing**—do not default to Arial. Pick a header font with personality and pair it with a clean body font.

| Header Font | Body Font |
|-------------|-----------|
| Georgia | Calibri |
| Arial Black | Arial |
| Calibri | Calibri Light |
| Cambria | Calibri |
| Trebuchet MS | Calibri |
| Impact | Arial |
| Palatino | Garamond |
| Consolas | Calibri |

| Element | Size |
|---------|------|
| Slide title | 36–44pt bold |
| Section header | 20–24pt bold |
| Body text | 14–16pt |
| Captions | 10–12pt muted |

### Spacing

- 0.5" minimum margins
- 0.3–0.5" between content blocks
- Leave breathing room—do not fill every inch

### Avoid (Common Mistakes)

- **Do not repeat the same layout**—vary columns, cards, and callouts across slides
- **Do not center body text**—left-align paragraphs and lists; center only titles
- **Do not skimp on size contrast**—titles need 36pt+ to stand out from 14–16pt body
- **Do not default to blue**—pick colors that reflect the specific topic
- **Do not mix spacing randomly**—choose 0.3" or 0.5" gaps and use them consistently
- **Do not style one slide and leave the rest plain**—commit fully or keep it simple throughout
- **Do not create text-only slides**—add images, icons, charts, or visual elements; avoid a plain title plus bullets
- **Do not forget text box padding**—when aligning lines or shapes with text edges, set `margin: 0` on the text box or offset the shape to account for padding
- **Do not use low-contrast elements**—icons AND text need strong contrast against the background; avoid light text on light backgrounds or dark text on dark backgrounds
- **NEVER use accent lines under titles**—these are a hallmark of AI-generated slides; use whitespace or background color instead

## Profer Official Preview (Required)

After generating or modifying a PPTX, you must open it in the official file preview of the current Profer Agent session so the user and Agent can continue working around the same file: first use `open_file_preview` to request that the existing PreviewPanel/PreviewTabContent refresh or open the PPTX, and wait for a viewer-ready acknowledgment matching the current revision; then use `inspect_file_preview` to read the overview, specified pages, or all pages from the **same user-visible viewer**. Do not create `Preview.html`, convert the PPTX into a local web page, or use `BrowserPreviewOpen`, `BrowserScreenshot`, Quick Look, or any separate screenshot path as a substitute for the official Profer PPT preview. Browser tools are only for when the user explicitly requests visiting a web page or previewing HTML/web PPT.

A ready response from `open_file_preview` only proves that the current revision has been loaded by the official viewer; it does not mean the visual design has passed. You must use `inspect_file_preview` to actually observe the pages before evaluating them. After modifying the PPTX, call `open_file_preview` again, wait for the new revision to be ready, and then inspect the affected pages again. Structural, content, and editability checks must still be performed separately.

## QA (Required)

**Assume there are problems. Your job is to find them.**

Your first render is almost never correct. Approach QA as a bug hunt, not a confirmation step. If you found zero issues on first inspection, you were not looking hard enough.

### Content QA

```bash
python -m markitdown output.pptx
```

Check for missing content, typos, and incorrect order.

**When using templates, check for leftover placeholder text:**

```bash
python -m markitdown output.pptx | grep -iE "xxxx|lorem|ipsum|this.*(page|slide).*layout"
```

If grep returns results, fix them before declaring success.

### Visual QA

In Profer, first use `open_file_preview`, then use `inspect_file_preview` to read page images from the same official viewer. Only when the current runtime does not provide these two tools may you use the offline conversion method below for auxiliary inspection; offline conversion cannot substitute for the official shared Profer preview.

**⚠️ USE SUBAGENTS** — even for 2–3 slides. You have been staring at the code and will see what you expect, not what is there. Subagents have fresh eyes.

When visually inspecting page images returned by the official preview, use:

```
Visually inspect these slides. Assume there are issues — find them.

Look for:
- Overlapping elements (text through shapes, lines through words, stacked elements)
- Text overflow or cut off at edges/box boundaries
- Decorative lines positioned for single-line text but title wrapped to two lines
- Source citations or footers colliding with content above
- Elements too close (< 0.3" gaps) or cards/sections nearly touching
- Uneven gaps (large empty area in one place, cramped in another)
- Insufficient margin from slide edges (< 0.5")
- Columns or similar elements not aligned consistently
- Low-contrast text (e.g., light gray text on cream-colored background)
- Low-contrast icons (e.g., dark icons on dark backgrounds without a contrasting circle)
- Text boxes too narrow causing excessive wrapping
- Leftover placeholder content

For each slide, list issues or areas of concern, even if minor.

Read and analyze these images:
1. /path/to/slide-01.jpg (Expected: [brief description])
2. /path/to/slide-02.jpg (Expected: [brief description])

Report ALL issues found, including minor ones.
```

### Verification Loop

1. Generate slides → use `open_file_preview`, wait for the revision-ready acknowledgment → use `inspect_file_preview`
2. **List issues found** (if none are found, look again more critically)
3. Fix issues
4. Use `open_file_preview` again, wait for the new revision → **re-verify the affected slides**
5. Repeat until a full pass reveals no new issues

**Do not declare success until you have completed at least one fix-and-verify cycle.**

## Converting to Images

Only in a non-Profer environment or when the official preview tools are unavailable may you convert the presentation offline into per-slide images for auxiliary inspection; do not use this as a substitute for official Profer preview acceptance.

**On Profer local machines (Windows + Office), prefer PowerPoint COM conversion** (PowerPoint is installed locally; LibreOffice/Poppler are not installed):

```bash
powershell -File scripts/office/pptx2png.ps1 -InputPath output.pptx
```

This generates `render/slide-01.png`, `render/slide-02.png`, and so on, at 1280×720 resolution.

On environments without Office, use LibreOffice + Poppler:

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
pdftoppm -jpeg -r 150 output.pdf slide
```

This creates `slide-01.jpg`, `slide-02.jpg`, and so on.

To re-render specific slides after fixes:

```bash
pdftoppm -jpeg -r 150 -f N -l N output.pdf slide-fixed
```
