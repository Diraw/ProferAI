# Profer 设置页细分规划：拆分「使用偏好」

日期：2026-09-28
状态：已实施（2026-09-28，typecheck 与 settings-macos-contract 契约测试通过）

## 背景与问题

当前设置导航（`SettingsPanel.tsx`）共分 6 组、约 15 个 tab：

| 分组 | Tab |
|---|---|
| （起始） | 通用偏好 |
| 账户 | 账户与资料、额度与用量、订阅方案、团队管理 |
| 模型与能力 | 模型配置、Agent 配置、提示词管理、Chat 工具 |
| 体验 | 外观设置、快捷键管理、Profer 教程 |
| 连接 | 远程连接、代理设置 |
| 系统 | 数据管理、(开发者)、(插件)、关于/更新 |

核心问题集中在 **通用偏好**（`GeneralSettings.tsx`）——它是事实上的「杂物桶」，一个页面塞了三个互不相关的 section、14+ 个开关：

1. **工作流与界面**：语言、快捷任务、界面引导、对话自动归档、消息钉顶、长文本粘贴转附件、富文本渲染、紧凑输入框（3 个数值）
2. **通知与声音**：通知开关、提示音开关、音效选择与自定义音效管理
3. **系统环境**：开机自启、Windows Shell 选择、浏览器主页

用户痛点：
- 「使用上的设置」（通知、对话浏览、输入体验）散布在「通用偏好」一个长页里，找一个开关要翻整个滚动区；
- 「系统环境」这类装完只改一次的项与高频调的使用项混在一起，层次不清；
- 「体验」组里已有外观/快捷键，对话与输入这类同类体验设置却在另一个 tab，心智不一致。

## 目标

把「使用中每天都会碰」的设置拆为独立的**使用偏好**页，让「通用偏好」瘦身成真正的系统级通用配置。

## 方案：新导航结构

```text
设置
├─ 通用 ────────────── general（瘦身：只保留系统级与环境配置）
├─ 使用偏好 ─────────── usage（新 tab，承接高频使用开关）
├─ 账户
│   ├─ 账户与资料
│   ├─ 额度与用量
│   ├─ 订阅方案
│   └─ 团队管理
├─ 模型与能力
│   ├─ 模型配置
│   ├─ Agent 配置
│   ├─ 提示词管理
│   └─ Chat 工具
├─ 体验
│   ├─ 外观设置
│   ├─ 快捷键管理
│   └─ Profer 教程
├─ 连接
│   ├─ 远程连接
│   └─ 代理设置
└─ 系统
    ├─ 数据管理
    ├─ （开发者模式：开发者、插件）
    └─ 关于/更新
```

### 新 tab「使用偏好」（usage）内容归属

从「通用偏好」迁出，按使用场景分三个 section：

| Section | 内容 | 来源 |
|---|---|---|
| 通知与声音 | 通知开关、提示音开关、内置/自定义音效管理 | GeneralSettings「通知与声音」整段 |
| 对话浏览 | 对话自动归档天数、消息钉顶摘要 | GeneralSettings「工作流与界面」前半 |
| 输入体验 | 长文本粘贴转附件、富文本渲染、紧凑输入框阈值/最小/最大高度 | GeneralSettings「工作流与界面」后半 |

### 瘦身后的「通用偏好」（general）

| Section | 内容 |
|---|---|
| 工作流与引导 | 语言、快捷任务、界面引导（重播 Coach Tour） |
| 系统环境 | 开机自启、Windows Shell、浏览器主页（原样保留） |

### 不改动的部分

- 账户、模型与能力、连接、系统各组保持现状（Agent 配置里的「显示/自动预览修改文件」属于 Agent 行为，留原位）；
- Chat 工具页内的语音输入（豆包）留原位——它与工具/MCP 同属「能力配置」，不属于使用体验；
- `AUTH_REQUIRED_TABS`、未登录过滤逻辑、tabsOverride 白名单流程不变——新 tab 不需要鉴权，天然纳入现有机制。

## 实施步骤

1. **`atoms/settings-tab.ts`**：`SettingsTab` 联合类型新增 `"usage"`。
2. **新建 `UsageSettings.tsx`**：从 `GeneralSettings.tsx` 整体搬出「通知与声音」section、「工作流与界面」中的对话浏览/输入体验部分，及随附的 atom 引用（`@/atoms/notifications`、`@/atoms/ui-preferences`）、紧凑输入框本地草稿态与自定义音效弹窗组件。
3. **精简 `GeneralSettings.tsx`**：仅保留工作流与引导 + 系统环境；删除已迁出代码与失效 import。
4. **`SettingsPanel.tsx`**：
   - 起始组改为两项：`general` 通用、`usage` 使用偏好（图标建议 `Settings` / `SlidersHorizontal`，lucide 已有）；
   - `renderTabContent` 增加 `case "usage"`。
5. **验证**：
   - `settings-macos-contract.test.ts` 若断言 tab 列表/通用页内容需同步更新；
   - `apps/electron` typecheck + 手动点检：新 tab 渲染、各开关读写回环、未保存确认流程（仅 channels 用，不受影响）、tab 回落逻辑（旧持久化的 activeTab 值仍有效，无需迁移）。

## 命名备选

- **使用偏好**（推荐）：直述「使用中的偏好」，与「通用偏好」形成「系统级 vs 使用级」的对偶。
- 交互与通知：更贴内容，但只允许「体验」语义，覆盖不住自动归档这类行为项。
- 任务与提醒：偏窄。

## 二次整理（2026-09-28，已实施）

- 语音输入（豆包流式）从「Chat 工具」页迁至「使用偏好」，页内标题改为「语音输入（豆包流式）」；Chat 工具页回归纯工具配置（联网搜索 / AI 图片生成 / 自定义工具）
- Agent 配置页的「显示」section（自动预览修改中文件、输出完保持展开）迁至「使用偏好」新 section「Agent 执行展示」；Agent 配置页只留思考强度与内置工具概览
- 导航新增「帮助」组（Profer 教程 + 关于/更新）置于末尾；「体验」组收敛为纯偏好（外观设置 + 快捷键管理）；「系统」组只留数据管理（开发者模式追加开发者/插件）

## 风险与说明

- 持久化的 `activeTab` 无需迁移：新 id 是纯增量。
- 「通用偏好」内文案「控制任务入口、对话浏览和输入体验」需同步改写，避免迁移后 description 与内容不符。
- 紧凑输入框的三个数值项较重（含实时窗口高联动提示），迁移时建议原样整段搬，不顺手重构，降低回归面。
